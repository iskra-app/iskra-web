# Аудит безопасности Iskra Web

Дата: 2026-10-22, поверх `0c7a6fc`. Порядок и направления — по `iskra/docs/iskra-audit-prompt.md`
(раздел «Кибербезопасность»), перенесённые с iOS на веб. Три параллельных среза:

1. **Чужой контент и браузер** — отрисовка HTML из событий, ссылки и адреса, CSP и Trusted Types,
   заголовки, nginx, service worker, `BroadcastChannel`.
2. **Вход и сессия** — OAuth/SSO/пароль, возврат с кодом, хранение токенов, жизненный цикл
   сессии и вкладок, выход, логи, демо-сервер.
3. **E2EE и медиа** — верификация и восстановление, «Отправить всё равно», шифрование и
   метаданные вложений, поисковый индекс, зависимости.

Каждая находка помечена **CONFIRMED** (прочитано в коде, путь прослежен; где можно — тестом,
который падает на старом коде) или **PLAUSIBLE** (зависит от поведения браузера или SDK, которое
из кода не видно).

**Исходное состояние.** `pnpm lint` — чисто, `pnpm check` — 0 ошибок, `pnpm test` — 408 зелёных,
`pnpm build` — собирается. `pnpm audit --prod` — «No known vulnerabilities found».

**Итог.** Критичных находок нет. Пути «злой собеседник или сервер → исполнение кода» не найдено:
DOMPurify с белым списком, ни одного `innerHTML`/`{@html}` в своём коде, CSP без
`unsafe-inline` и Trusted Types с тремя именованными политиками. Серьёзное — в другом: в том, что
теряется или утекает *без* атаки (ключи шифрования при сбое обновления токена, метаданные фото
при сбое перерисовки, токены на диске при сбое выхода).

## Оставлено — нужно решение автора

### A1 (вторая часть). Мягкий выход стирает всё — high, CONFIRMED

`HttpApiEvent.SessionLoggedOut` приходит и с `soft_logout: true` (сервер завершил сеанс, но
устройство живо), а `sessionEnded` стирает базы, ключи E2EE, поиск и запись аккаунта в любом
случае. Нативная держится правила «мягкий выход ничего не удаляет».

Починить «не стирать» мало: при новом входе устройство новое, и старые базы ему не годятся (A3).
Правильно — **войти снова в тот же сеанс**: при `soft_logout` остановить клиент, оставить базы и
запись, показать вход с подставленным аккаунтом и передать прежний `device_id` (пароль — полем
`device_id` в `m.login.password`, OAuth — `deviceId` в `OAuth2`, legacy SSO его не умеет). Это
отдельная фича со своим экраном и строками, поэтому не сделана в рамках аудита.

Враждебный сервер может стереть локальные ключи и так — жёстким выходом (`soft_logout: false`);
это так у всех клиентов, Element тоже. Опасность в другом: мягкий выход — штатный инструмент
администратора, и у пользователя без резервной копии он уносит историю.

### W1. Ночная сборка встраивается во фрейм — medium, CONFIRMED

`nightly.web.iskra.wtf` — GitHub Pages, CSP только тегом `<meta>`, где `frame-ancestors` не
работает; ни COOP, ни `X-Content-Type-Options`. На неё входят настоящими аккаунтами, а значит,
чужая страница может встроить её и подсунуть нажатие («Подтвердить вход», «Присоединиться»).
Решается вне кода: Cloudflare перед Pages с заголовками из `security-headers.ts` или ночная
сборка на том же VPS (`headers.nginx` уже собирается). Frame-buster в `boot.ts` — слабая замена.

### A7. Запись прошлого аккаунта остаётся и «воскресает» — low, PLAUSIBLE

Если у Алисы сеанс не поднялся («хранилище недоступно» — запись не удаляется, это сознательно:
удалить ключи необратимо) и на том же экране входит Боб, то после выхода Боба на следующем запуске
`vault.current()` откроет сеанс Алисы. Нужна явная модель: «на устройстве один аккаунт» —
предлагать убрать прежний до входа нового; или список аккаунтов, как в нативной.

### E3. Метаданные не во всех форматах — low, PLAUSIBLE

- GIF не перерисовывается (убило бы анимацию) и уходит как есть — с комментариями и XMP, если
  они в нём были.
- WebM/MKV без сжатия уходят как есть: разбирать их нечем. В записи экрана браузером о человеке
  ничего нет; в видео с камеры — может быть.
- `mp4Metadata.ts` вырезает известные боксы; результат по белому списку не перечитывается, в
  отличие от нативной (`MetadataStripper.isClean`).
- HEIC/TIFF — `file`, уходят файлом, нетронутыми (как «файл» в нативной).

### E1. «Отправить всё равно» не показывает, кому доверяет — low, CONFIRMED

`trustUnsignedDevices` помечает `LocalTrust.Ignored` все неподписанные владельцами устройства
проверенных участников комнаты — навсегда. Набор совпадает с тем, на чём застряла отправка (крипто
отказывает ровно из-за них), так что шире, чем в нативной, это не выходит. Но человек не видит
*какие* это устройства. Улучшение — список в подтверждении; и `olmMachine` достаётся через
приведение типов — при смене внутренностей SDK кнопка тихо перестанет работать.

### Мелкое

- **E7** — квитанции о прочтении только публичные (`m.read`); `m.read.private` нет. Сверить с
  нативной, есть ли там переключатель.
- **E8** — `dompurify`, `matrix-js-sdk`, `matrix-encrypt-attachment` с `^` в `package.json`
  (версии фиксирует lock-файл). `matrix-encrypt-attachment` 1.0.3 почти не поддерживается — хэш
  он проверяет, но замену стоит запланировать.
- **W5** — диалог «Открыть ссылку» не показывает `via`: присоединение может пойти через сервер
  из ссылки (утекает только факт и время).
- **W6** — HSTS без `includeSubDomains`; нет `Cross-Origin-Resource-Policy`.
- **W7** — source maps на боевом сервере. Исходники открыты, утечки нет.
- **A10** — `warn`/`error` SDK идут в консоль (сознательно: так видны сбои). Токены SDK туда не
  кладёт; тела ответов OAuth в ошибках — могут.
- Поисковый индекс не чистится при уходе из комнаты; удалённое на другом устройстве, если
  редакция не дошла до индексатора, остаётся находимым до «Очистить кэш».

## Проверено и в порядке

**Чужой контент.** Во всём `src/` нет `{@html}`, `innerHTML`, `outerHTML`, `insertAdjacentHTML`,
`eval`, `new Function`. `formatted_body` — DOMPurify с белым списком тегов Matrix, атрибуты
`href alt title start data-mx-spoiler`, без `style`/`class`/`src`; ссылки — только
`https`/`http`/`mailto`, всегда `noopener noreferrer`; `<img>` заменяется подписью (ни `mxc://`,
ни чужой `https:` не грузятся — адрес читающего не раскрывается); вставка — `replaceChildren`
фрагмента. Всё остальное (имена, темы, опросы, файлы, цитаты) — текстовыми интерполяциями
Svelte. `linkify` строит сегменты, а не HTML. Геоссылки собираются из чисел.

**CSP и заголовки.** Боевая: `script-src 'self' 'wasm-unsafe-eval'`, `style-src 'self'`,
`object-src 'none'`, `base-uri 'none'`, `frame-ancestors 'none'`, `form-action 'self'`,
`require-trusted-types-for 'script'` и три политики (`iskra-sw` пропускает ровно `sw.js`).
`connect-src https:` — сознательный компромисс (homeserver вводит человек). Заголовки — из одного
источника во все `location` nginx. `Referrer-Policy: no-referrer`, COOP `same-origin`.

**Service worker.** Только оболочка (`html js css wasm svg png webmanifest`) и свои шрифты. Ни
ответов API, ни медиа — расшифрованное в Cache Storage не попадает.

**Вход.** Код и `state` стираются из адреса `replaceState` первой строкой `main.ts`, до роутера,
SDK и SW. PKCE S256, `state` — 16 случайных байт. `http:` — только localhost; `.well-known` — только
`https:`. Демо — только своим `fetchFn` клиента (глобальный `fetch` не подменяется), только по
адресу в зоне `.invalid`; реальный аккаунт не трогает.

**Секреты.** Токены и ключ криптохранилища — под AES-GCM-256, свой ключ на аккаунт, IV 12
случайных байт на запись. В `localStorage`/`sessionStorage` токенов нет. Выход стирает базу
синхронизации, обе крипто-базы, индекс, черновики, локальные имена, обои, запись аккаунта.

**Вкладки.** Web Locks на аккаунт; токен обновляет только держатель лока; `BroadcastChannel` —
same-origin, сообщения проверяются (`parseRoute`, только `open`).

**E2EE.** Своей Matrix-криптографии нет; `crypto.subtle` — только `secretBox.ts` и HMAC индекса.
Вложения в зашифрованных комнатах — `matrix-encrypt-attachment` (файл и миниатюра), стикер в
зашифрованной — `m.image`, не `m.sticker`. При скачивании SHA-256 проверяется, вложение без хэша
отбрасывается; чужой `mimetype` сводится к белому списку. Строгий режим
(`AllDevicesIsolationMode(true)`). SAS — только свои устройства, «не совпадают» → `mismatch()`.
Ключ секретного хранилища — только на время операции. `preview_url` не вызывается.
