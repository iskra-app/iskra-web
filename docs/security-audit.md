# Аудит безопасности Iskra Web

Дата: 2026-10-22, поверх `0c7a6fc`. Порядок и направления — по `iskra/docs/iskra-audit-prompt.md`
(раздел «Кибербезопасность»), перенесённые с iOS на веб. Три параллельных среза:

1. **Чужой контент и браузер** — отрисовка HTML из событий, ссылки и адреса, CSP и Trusted Types,
   заголовки, nginx, service worker, `BroadcastChannel`.
2. **Вход и сессия** — OAuth/SSO/пароль, возврат с кодом, хранение токенов, жизненный цикл
   сессии и вкладок, выход, логи, демо-сервер.
3. **E2EE и медиа** — верификация и восстановление, «Отправить всё равно», шифрование и
   метаданные вложений, поисковый индекс, зависимости.

Каждая находка помечена **CONFIRMED** (прочитано в коде, путь прослежен; где можно — тестом,
который падает на старом коде) или **PLAUSIBLE** (зависит от поведения браузера или SDK, которое
из кода не видно).

**Исходное состояние.** `pnpm lint` — чисто, `pnpm check` — 0 ошибок, `pnpm test` — 408 зелёных,
`pnpm build` — собирается. `pnpm audit --prod` — «No known vulnerabilities found».

**Итог.** Критичных находок нет. Пути «злой собеседник или сервер → исполнение кода» не найдено:
DOMPurify с белым списком, ни одного `innerHTML`/`{@html}` в своём коде, CSP без
`unsafe-inline` и Trusted Types с тремя именованными политиками. Серьёзное — в другом: в том, что
теряется или утекает *без* атаки (ключи шифрования при сбое обновления токена, метаданные фото
при сбое перерисовки, токены на диске при сбое выхода).

## Оставлено сознательно

- **E7** — квитанции о прочтении только публичные. В нативной переключателя нет, а она — эталон
  поведения: такая настройка заводится сначала там.
- **W7** — source maps на боевом сервере. Исходники открыты (GPL), прятать в них нечего, а
  отладке ночной сборки они нужны.
- **WebM без сжатия** уходит как есть: разбирать его нечем, а в записи экрана браузером о
  человеке ничего нет. HEIC/TIFF — файлами, нетронутыми, как «файл» в нативной.
- **`olmMachine` через приведение типов** в «Отправить всё равно»: `CryptoApi` не открывает
  `LocalTrust.Ignored`. Сменится внутренность SDK — кнопка тихо перестанет работать, и тест
  `timeline-store.test.ts` это поймает.
- **`matrix-encrypt-attachment` 1.0.3** почти не поддерживается; хэш он проверяет. Замена —
  отдельной задачей.

## Проверено и в порядке

**Чужой контент.** Во всём `src/` нет `{@html}`, `innerHTML`, `outerHTML`, `insertAdjacentHTML`,
`eval`, `new Function`. `formatted_body` — DOMPurify с белым списком тегов Matrix, атрибуты
`href alt title start data-mx-spoiler`, без `style`/`class`/`src`; ссылки — только
`https`/`http`/`mailto`, всегда `noopener noreferrer`; `<img>` заменяется подписью (ни `mxc://`,
ни чужой `https:` не грузятся — адрес читающего не раскрывается); вставка — `replaceChildren`
фрагмента. Всё остальное (имена, темы, опросы, файлы, цитаты) — текстовыми интерполяциями
Svelte. `linkify` строит сегменты, а не HTML. Геоссылки собираются из чисел.

**CSP и заголовки.** Боевая: `script-src 'self' 'wasm-unsafe-eval'`, `style-src 'self'`,
`object-src 'none'`, `base-uri 'none'`, `frame-ancestors 'none'`, `form-action 'self'`,
`require-trusted-types-for 'script'` и три политики (`iskra-sw` пропускает ровно `sw.js`).
`connect-src https:` — сознательный компромисс (homeserver вводит человек). Заголовки — из одного
источника во все `location` nginx. `Referrer-Policy: no-referrer`, COOP `same-origin`.

**Service worker.** Только оболочка (`html js css wasm svg png webmanifest`) и свои шрифты. Ни
ответов API, ни медиа — расшифрованное в Cache Storage не попадает.

**Вход.** Код и `state` стираются из адреса `replaceState` первой строкой `main.ts`, до роутера,
SDK и SW. PKCE S256, `state` — 16 случайных байт. `http:` — только localhost; `.well-known` — только
`https:`. Демо — только своим `fetchFn` клиента (глобальный `fetch` не подменяется), только по
адресу в зоне `.invalid`; реальный аккаунт не трогает.

**Секреты.** Токены и ключ криптохранилища — под AES-GCM-256, свой ключ на аккаунт, IV 12
случайных байт на запись. В `localStorage`/`sessionStorage` токенов нет. Выход стирает базу
синхронизации, обе крипто-базы, индекс, черновики, локальные имена, обои, запись аккаунта.

**Вкладки.** Web Locks на аккаунт; токен обновляет только держатель лока; `BroadcastChannel` —
same-origin, сообщения проверяются (`parseRoute`, только `open`).

**E2EE.** Своей Matrix-криптографии нет; `crypto.subtle` — только `secretBox.ts` и HMAC индекса.
Вложения в зашифрованных комнатах — `matrix-encrypt-attachment` (файл и миниатюра), стикер в
зашифрованной — `m.image`, не `m.sticker`. При скачивании SHA-256 проверяется, вложение без хэша
отбрасывается; чужой `mimetype` сводится к белому списку. Строгий режим
(`AllDevicesIsolationMode(true)`). SAS — только свои устройства, «не совпадают» → `mismatch()`.
Ключ секретного хранилища — только на время операции. `preview_url` не вызывается.

## Проверка после правок

После второго захода: `pnpm lint` — чисто; `pnpm check` — 0 ошибок; `pnpm test` — 55 файлов,
441 тест, все зелёные (было 408 в 49); `pnpm build` — собирается.

`pnpm e2e` на Chromium (телефон и десктоп): 215 зелёных, 19 пропущено. Красные были трижды
из-за `clipboard-read=()` в `Permissions-Policy` — e2e проверяют «Скопировать», читая буфер со
страницы; запрет убран (браузер и так спрашивает разрешение), `settings.spec` и `chat.spec` после
этого — 86 из 86. Ещё один красный — «кружочек» на телефоне (`voice.spec.ts:199`): падает так же
на исходном `0c7a6fc`, к аудиту не относится. WebKit и Firefox не гонялись.

**Не проверено вживую:** перерисовка 48 Мп фото в Safari на iPhone (E2 — тестом на пути отказа);
429 от настоящего MAS (A1 — тестом против SDK); мягкий выход от настоящего Synapse и вход с
прежним `device_id` (A1 — на демо-сервере, который ведёт себя по спецификации).
